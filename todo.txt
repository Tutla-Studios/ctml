CraftyTML - left undone
=======================

Every line is a bug or a caveat that is still true of the code, labelled by how much it matters:

  CRITICAL    silently wrong or leaves the ui stuck, and nothing says so
  WARN        a real limit worth knowing before building on it
  SUGGESTION  a rough edge or a cost, fine as it stands


RENDERER / PAINT  (render/CTMLRenderer.java)
--------------------------------------------
- SUGGESTION: opacity is drawn as a group rather than composited. Everything inside a faded box is drawn
  at the group's alpha, and whatever an opaque square background of the group covers is left out of the
  draws under it, so the ordinary overlap no longer darkens twice. Nothing on the gui side can draw a
  subtree off screen and fade the result, so two translucent children of a faded box, or two under a
  rounded or translucent background, do still show through one another.
- SUGGESTION: a background image is one layer, and how big it is comes from the size read off the front
  of the png. Anything else a texture can be, an atlas sprite among them, has no size to cover or
  contain with and is stretched over the whole box instead. No background-origin, no
  background-attachment, no repeat-space or repeat-round, and a rounded box draws its tiles once per
  row of its corners rather than once.

LAYOUT  (render/CTMLLayout.java)
--------------------------------
- WARN: a table collapses its borders by sliding the cells onto one another by the width of the first
  border it finds, so a table whose cells carry different border widths has them overlap by the
  wrong amount. There is no border-spacing, no col or colgroup, and no visible-row collapsing.
- WARN: a float is placed where it was written in the flow rather than on the line it appears on, so one
  written between two words sits above that line instead of inside it. There is no shape-outside.
- WARN: grid has one track list per axis: no named lines, no areas, no subgrid, no dense packing and no
  minmax(). An fr track only has room to share where its axis has a definite size, and an auto
  track is sized from the items sitting in one track alone, not from the ones spanning several.
- SUGGESTION: a multi column block never splits a child down the middle, so its columns are only as even
  as whole children allow and a child taller than its share makes its column taller.


OVERFLOW AND SCROLLING  (render/CTMLScroll.java)
------------------------------------------------
- WARN: the keyboard reaches scroll containers and nothing else. There is no focus to speak of: the
  keys go to whatever was last pressed on or wheeled over, nothing draws a focus ring, and tab
  moves through nothing.
- SUGGESTION: scroll anchoring holds the first child showing through the scrollport, and only on the
  y axis. Something resizing inside that child still moves what is under the eye, and a container
  whose children are all one box has nothing to hold on to.
- SUGGESTION: scrollIntoView brings a box in from the nearest edge in one pass, so a box inside two
  scroll containers at once is brought the rest of the way on the frame after.
- SUGGESTION: scroll-smooth slides the wheel and the keys as well as the scrolls a script asks for.
  Css only promises the last of those.


STYLE SYSTEM  (ctml/ElementStyle.java, ctml/style/*)
----------------------------------------------------
- WARN: no variants at all: hover:, focus:, active:, dark:, md: and friends come back from the
  parser as unknown.
- WARN: the text initial values only exist on <ctml>, since a default on every element would block
  the parent's value from ever reaching a child, so an element laid out with no ctml root above
  it has no colour or font size to fall back on bar the renderer's own constants.
- SUGGESTION: css color keywords (cornflowerblue, rebeccapurple) are not supported; only the tailwind
  palette, where a bare family name (text-green) falls back to that family's 500 shade
  and [#hex]. A stop whose colour nothing knows is left out, so the gradient comes up one stop
  short and is not drawn at all.
- SUGGESTION: no box-shadow, outline, cursor, font-family, transform, transition or animation.
- SUGGESTION: there is no way to set defaults from a script, and no per element reset: a new element
  has to override defaultStyle() in java.
- SUGGESTION: gradient colour interpolation modifiers (bg-linear-to-r/oklch, /srgb-linear) are not
  read, and every ramp is mixed channel by channel in plain srgb.
- SUGGESTION: a from- / via- / to- class with no shape class before it assumes bg-linear-to-r, and
  writes the background gradient; the text one is written by text-from- / text-via- / text-to-.


SCREEN AND REGISTRY  (render/CTMLScreen.java, render/UIRegistry.java, CraftytmlClient.java)
-------------------------------------------------------------------------------------------
- SUGGESTION: a drag of a box or of a scrollbar thumb ends on mouseReleased, and there is still no way
  to read the live button state back: this build is on sdl, so there is no glfwGetMouseButton to ask.
  A release that never arrives is worked out from the cursor instead, since a button that is down
  reports every movement it makes, so one that moves with nothing reported lets go within a few
  frames. A release lost while the cursor then never moves again is still held, until it moves or
  anything at all is pressed; nothing moves in the meantime, so it costs nothing but the grip.
- WARN: no hot reload: editing a .ctml file needs a game restart.
- WARN: CTMLScreen routes dragging, scrolling and the scrolling keys, and the press side of the first
  two only answers the left button. No click handlers (the callback property is registered and never
  called), no hover, no narration.
- WARN: no widget elements: ctml, div, span and the table tags are all there is. No button, input,
  img, list.
- SUGGESTION: the button numbers in mouseClicked / mouseDragged / mouseReleased are sdl's: left is 1,
  middle 2, right 3, not glfw's 0 / 1 / 2. MouseHandler's isLeftPressed / isRightPressed are no use
  on a screen at all, since minecraft only keeps them up to date while no screen is open.
- SUGGESTION: hit testing ignores border-radius (the corners of a rounded box are live) and a box faded
  by an ancestor's opacity rather than its own.
