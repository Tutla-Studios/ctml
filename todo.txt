CraftyTML - left undone
=======================

RENDERER / PAINT  (render/CTMLRenderer.java)
--------------------------------------------
- border-radius is faked: corners get cut off with three fills, there is no rounded
  rect primitive. Looks like a chamfer, not a radius.
- background-image is parsed into the style and never drawn.
- Only one border-color for all four sides. No per-side colors, no border styles.
- opacity multiplies the alpha of each thing drawn instead of compositing the subtree,
  so overlapping children inside a faded box darken each other.
- letter-spacing is stored and ignored.
- Fractional font scales (text-xs is 0.75) go through the matrix, so small text is blurry.
- No vertical centering of text inside its box.
- z-index sorts siblings at paint time only, so it cannot lift a box above its parent's
  siblings: there are no stacking contexts, opacity and overflow start none, and a child
  with a high z-index still paints under an uncle box drawn later.
- Gradients ignore border-radius, so a rounded box with a gradient gets square corners,
  and background-color is skipped entirely when a gradient is set instead of drawn under it.
- Diagonal gradient directions (bg-gradient-to-tr and the rest) are drawn as the plain
  horizontal ramp.
- Horizontal gradients are one fill per pixel column, so a screen wide one is ~850 draws
  a frame. Vertical ones go through fillGradient and cost one draw per segment.
- Gradient text is drawn glyph by glyph with graphics.text, which drops the per glyph
  bold / italic styles the line carries and measures advances off the plain character.
  Each glyph is its own draw call, and the shadow is drawn in the ramp colour too.
- text-gradient takes over from color entirely; there is no bg-clip-text, so a gradient
  cannot be clipped to text while the box keeps its own background.
- The only way to scroll is the wheel and the bars. No keyboard (there is no focus to hang it
  on), no scroll-into-view, no scroll anchoring and no animation: a scroll lands at once.
- No overscroll-behavior, so a box at its end always hands the turn of the wheel outwards.
- A scroll offset is kept in gui pixels on the element, and like a drag offset it is not
  rescaled when the gui scale or the window changes and is lost on reload. Nothing exposes it
  to a script either, so there is no way to scroll a box from code.
- scrollbar-gutter is all or nothing: css's stable / both-edges is not there, and the gutter
  takes its room out of the content rather than growing the box.


LAYOUT  (render/CTMLLayout.java)
--------------------------------
- A multi column block never splits a child down the middle, so its columns are only as even as
  whole children allow and a child taller than its share makes its column taller.
- A float is placed where it was written in the flow rather than on the line it appears on, so one
  written between two words sits above that line instead of inside it. There is no shape-outside.
- A box that keeps a scrollbar gutter lays its children out twice, since the room the bar takes can
  change what overflows. An arrangement that will not settle keeps the bar rather than flickering.


STYLE SYSTEM  (ctml/ElementStyle.java, ctml/style/*)
----------------------------------------------------
- No variants at all: hover:, focus:, active:, dark:, md: and friends come back from the
  parser as unknown.
- Unknown classes are only printed to stdout by applyClassStyles, with no line number and
  nothing the interpreter can report.
- A class whose value makes no sense for its key (auto on a gap, a percent on a radius)
  is also silently ignored.
- No box-shadow, outline, cursor, font-family, transform, transition or animation.
- The text initial values only exist on <ctml>, since a default on every element would block
  the parent's value from ever reaching a child, so an element laid out with no ctml root above
  it has no colour or font size to fall back on bar the renderer's own constants.
- There is no way to set defaults from a script, and no per element reset: a new element
  has to override defaultStyle() in java.
- bg-gradient-* / text-gradient-* are tailwind v3 spelling. v4's bg-linear-to-r,
  bg-radial and bg-conic are not recognised, and neither are gradient colour stop
  positions (from-10%) or interpolation modifiers (/oklch).
- from- / via- / to- always write the background gradient and text-from- / text-via- /
  text-to- the text one, so a stop class on its own (no direction class) silently assumes
  to-r. A stop with an unknown colour is dropped and leaves the gradient half built.


SCREEN AND REGISTRY  (render/CTMLScreen.java, render/UIRegistry.java, CraftytmlClient.java)
-------------------------------------------------------------------------------------------
- No hot reload: editing a .ctml file needs a game restart.
- CTMLScreen routes nothing but dragging and scrolling, and the press side of both only answers
  the left button. No click handlers, no focus, no keyboard, no hover, no narration.
- No widget elements: only ctml, div and span exist. No button, input, img, list.
- Dragging goes through mouseClicked / mouseDragged / mouseReleased, and the button numbers
  there are sdl's: left is 1, middle 2, right 3, not glfw's 0 / 1 / 2. MouseHandler's
  isLeftPressed / isRightPressed are no use on a screen at all, since minecraft only keeps
  them up to date while no screen is open.
